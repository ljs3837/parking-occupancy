# 김태수 — 개인별 6주 할 일

[팀 전체 일정](TEAM_SCHEDULE_6week.md) · [개인별 문서 목록](README.md)

담당: **차량 인식·주차면 점유 판정** · 주요 작업 경로: `src/parking/perception/live.py, occupancy.py, tracker.py`

작업 기준은 주 12시간, 총 72시간이다. 매주 구현·실험 8시간, 공동 데이터·검수 1.5시간, 리뷰·통합·회의 1.5시간, 예비 1시간으로 배분한다. 아래 항목은 계획이며 완료 후에만 체크한다. 팀 전체 일정이 바뀌면 이 문서도 함께 수정한다.

## 협업과 전달 사항

- 받는 자료: 이종수에게 면 ID·폴리곤을 받고, 엄승연에게 원본 프레임·관측 시각을 받는다.
- 전달할 자료: 엄승연에게 면별 vacant/occupied/unknown·가림·신뢰도·관측 시각·유지 여부를 전달한다. 류채연에게 상태 예측·전환 로그와 규칙 버전을 제공한다.
- 내 코드 검토자: **이종수**.
- 내가 검토할 코드: **엄승연**의 작업.
- 담당 기능의 오류는 직접 수정하고, 다른 영역의 오류는 로그·재현 입력과 함께 담당자에게 전달한다.

## 1주차 — 기준 확정과 병렬 개발 준비

- [ ] 차량 추론 실행
- [ ] 면-차량 대응 기준 설계
- [ ] 빈자리·점유·불명 및 영상 주차완료 정의
- [ ] 샘플 상태 출력

**내 결과물:** 상태 판정 규칙 초안, 차량 검출 샘플, 상태 출력 샘플

**함께 할 일:** 각자 20장 시범 색인 후 소요 시간을 측정한다. 이종수→김태수→류채연→엄승연→이종수 순서로 정답을 교차 검수한다. 모델이 준비되지 않아도 샘플 결과로 통합을 진행한다.

**팀 통과 기준:** 전원이 같은 예제를 실행하고, 폴리곤 좌표·클래스·상태·파일 형식에 합의한다. 데이터·장비 확보가 부족하면 이 주에 지원 조건과 수량을 줄인다.

## 2주차 — 이미지에서 자동 결과까지 연결

- [ ] 정답 면 기준 차량-면 대응 구현
- [ ] 각 면의 3상태 판정
- [ ] 차량 없는 통로 오판 점검
- [ ] 클래스 순서를 모델 정보로 확인

**내 결과물:** 면별 점유 추론 모듈, 상태 샘플, 기본 검증 사례

**함께 할 일:** 동일한 실내·실외 샘플로 전체 흐름을 검토한다. 면 발견 오류와 점유 오류를 구분해 기록한다. CNN 경로가 실제 CNN 대신 차량 YOLO를 사용하는 기존 부분은 지원 상태를 명확히 표시한다. 별도 CNN 실험은 기본 경로 완성 후 여유가 있을 때만 한다.

**팀 통과 기준:** 수동 면 작성 없이 이미지에서 자동 주차면과 상태가 표시되고 결과를 다시 열 수 있다. 자동 면 출력이 없으면 류채연이 데이터 변환·실험 자동화를 지원하며 다른 문서 작업은 재배분한다.

## 3주차 — 영상과 시간 변화 처리

- [ ] 면별 상태 이력·안정화 구현
- [ ] 통로 통과 차량·잠깐 진입 구분
- [ ] 가림·관측 만료 시 불명 처리
- [ ] 상태 전환 지연 측정

**내 결과물:** 안정화 모듈, 상태 변화 로그, 전환·가림 검증 영상

**함께 할 일:** 실내·실외 영상 각 1개 이상을 처음부터 끝까지 재생한다. 통합 오류는 각 모듈 소유자가 수정한다. 고정 영상에서 면 ID가 불필요하게 바뀌지 않는지 확인한다.

**팀 통과 기준:** 영상에서 위치·상태·개수가 갱신되고, 가림이나 오래된 관측이 확정 빈자리로 표시되지 않는다.

## 4주차 — 새로운 환경 검증과 주요 오류 개선

- [ ] 반사·그림자·부분 점유·통로 차량의 오판 개선
- [ ] 점유 임계값·안정화 시간 검증
- [ ] 빈자리 오안내 집중 점검

**내 결과물:** 상태별 성능표, 임계값 근거, 오안내 사례 비교

**함께 할 일:** 기능 범위를 동결하고 최종 평가 기준을 확정한다. 일반화가 부족하면 자동 제안+수정 기능을 보조 결과로 유지하며 완전 자동 성능을 따로 보고한다. 다중 카메라 등 새 기능은 추가하지 않는다.

**팀 통과 기준:** 미학습 검증 장소의 수치와 실패 조건이 있고, 개선 우선순위와 남은 작업이 정해져 있다. 실제 테스트 장소는 아직 튜닝에 사용하지 않는다.

## 5주차 — 모델 고정과 통합 안정화

- [ ] 최종 점유 규칙·임계값 고정
- [ ] 가림·유효시간·상태 전환 회귀 검사
- [ ] 판정 근거 문서화

**내 결과물:** 고정 상태 규칙, 검증 결과, 상태 판정 설명

**함께 할 일:** 모델·임계값·평가 코드를 고정하고 통합 오류만 수정한다. 통합 로그에서 발생한 오류는 담당별로 분배한다. 6주차 시연 장면과 실패 사례를 준비한다.

**팀 통과 기준:** 같은 입력에서 결과를 재현하고, 30분 실행 중 오류 종료가 없으며, 평가 명령과 앱이 같은 모델 버전을 사용한다.

## 6주차 — 최종 평가와 팀 인수

- [ ] 최종 점유·빈자리 오안내·전환 지연 확인
- [ ] 이미지와 영상의 판정 차이 설명
- [ ] 실패 사례 정리

**내 결과물:** 상태 판정 결과 자료, 규칙 인수 설명

**함께 할 일:** 실내·실외 이미지와 영상 시연, 다른 담당 모듈 실행, 코드·문서 리뷰를 완료한다. 최종 테스트를 보고 모델을 다시 조정하면 해당 결과는 개발 결과로 구분하고 추가 독립 검증 없이는 최종 일반화 성능으로 발표하지 않는다.

**팀 통과 기준:** 네 명 모두 앱을 실행할 수 있고, 자동 위치·상태·개수, 평가 결과, 한계, 설치 절차를 함께 제출한다.

## 매주 반복할 체크리스트

- [ ] 공동 색인·검수 시간을 채우고, 구도가 같아도 차량 상태는 이미지마다 확인한다.
- [ ] 담당 리뷰를 수행하고, 내 변경도 지정 검토자에게 전달한다.
- [ ] 실행 명령·입력·버전·결과 또는 평가 증거를 남긴다.
- [ ] 중간 회의에서 막힌 점을 공유하고 주말에 실제 투입 시간과 다음 작업을 기록한다.
- [ ] 다음 주 작업이 25% 이상 지연되거나 투입이 팀 평균보다 20% 이상 많으면 재배분을 요청한다.

## 개인 최종 인수 기준

- [ ] 1~6주차의 내 결과물과 실행 절차를 팀에 전달했다.
- [ ] 내 담당 기능의 성공·실패 사례와 지원 조건을 설명할 수 있다.
- [ ] 다른 팀원이 내 결과물을 실행하고 검토했다.
- [ ] 최종 모델·설정·데이터·코드 버전과 알려진 문제를 기록했다.
